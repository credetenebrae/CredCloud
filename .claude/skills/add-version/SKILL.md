# Новый коммит карты по статье

Контент сайта лежит в `index.html`, внутри `<script>`. Версионирование устроено как в git:
- `DATA` — базовый контент (корневой коммит): облака и темы. **Не правь DATA ради новой статьи** — всё новое идёт коммитами.
- `COMMITS` — коммиты. Каждый — набор правок к родителю (`parent`).
- `BRANCHES` — ветки: `имя → {color, head, recommended?}`. Ровно у одной ветки `recommended:true`: она открывается у посетителя по умолчанию и стоит первой в меню, следом база, дальше — по свежести. Переносить флаг на другую ветку — только если пользователь попросит. `head` — последний коммит ветки. Ветка — просто указатель, её содержимое = вся цепочка коммитов от `head` до корня (включая коммиты других веток, от которых она отросла).

## Формат коммита

```js
{id:'3f9c2a1', date:'2026-11-14 10:30', parent:'0a67d21', branch:'зелёная', title:'что поменялось', src:'https://статья', changes:[ … ]}
```

- `id` — короткий хеш, 7 символов `0-9a-f`. Сгенерировать: `node -e "console.log(require('crypto').randomBytes(4).toString('hex').slice(0,7))"`.
- `parent` — коммит, от которого отталкиваемся. Ровно у одного коммита `parent:null` (корень).
- `branch` — ветка, **в которой** сделан коммит (по нему меню группирует коммиты; цвет ветки виден только в меню, на карте правки не подсвечиваются).
- `date` — время коммита `'ГГГГ-ММ-ДД ЧЧ:ММ'` (взять: `date '+%F %R'`). По дате головы ветки меню сортирует ветки: свежие выше.
- `title` — сообщение коммита (одна строка в меню).
- `src` — ссылка на статью-источник («источник ↗»).

## Две операции

**Продлить ветку** (по умолчанию для новой статьи — ветку, которую пользователь назвал или на которой он сейчас):
1. Новый коммит: `parent` = текущий `BRANCHES[ветка].head`, `branch` = эта ветка.
2. Обнови `BRANCHES[ветка].head` = id нового коммита.

**Создать ветку** (когда пользователь просит новую ветку или статья — альтернатива уже существующему):
1. Новый коммит: `parent` = коммит, от которого ветвимся. По умолчанию — `head` ветки, на которой пользователь сейчас (как `git checkout -b` от текущего места), иначе — тот, что он назвал.
2. Новая запись в `BRANCHES`: `'имя': {color:'#…', head:'<id нового коммита>'}`. Цвет — заметно отличный от уже занятых.

Если неясно, продлить или ветвиться и от какого коммита, — спроси.

## Правки (`changes`)

| op | поля | что делает |
|---|---|---|
| `add` | `cloud`, `t`, `x` (или `adv:true` без `x`) | новая тема в облаке |
| `mod` | `cloud`, `t`, `x?`, `nt?` | меняет текст и/или название (`nt`) темы |
| `del` | `cloud`, `t` | убирает тему |
| `cloud` | `t`, `s?`, `o?` | новое большое облако (`o:1` — «самостоятельное», с контуром) |

- `cloud` и `t` должны **точно** совпадать с названиями с учётом всей истории родителей (если предок переименовал тему через `nt`, дальше — новое имя). Названия: `grep -n '{t:"' index.html` + `changes` коммитов-предков.
- Темы в новое облако (`op:'cloud'`) добавляй следующими `add` в том же коммите.
- `x` — по-русски, в тоне остальных облаков: конкретно и практично, столько, сколько нужно. Длинный текст на карте обрезается «…» и раскрывается при наведении. Можно `<code>…</code>` и `<b>…</b>`.
- `adv:true` — продвинутая тема: только заголовок, фиолетовая пунктирная рамка.

## Порядок работы

1. **Прочитай статью целиком** (WebFetch по ссылке или текст от пользователя). Выпиши **все** полезные практичные мысли, которых ещё нет на карте (с учётом истории выбранной ветки) — без ограничения по количеству: важна любая полезная информация, даже если правок получится очень много. Пересказ того, что уже есть, — не новый коммит.
2. **Сопоставь с облаками.** Дополнить существующую тему (`mod`), новая тема (`add`), новое облако (`cloud`) — только если тема не влезает ни в одно облако. Устаревшее по статье — `del`.
3. **Продлить или ветвиться** — см. «Две операции». Не забудь обновить `head`.
4. **Допиши коммит в конец `COMMITS`.**
5. **Проверь:**
   ```bash
   node .claude/skills/add-version/scripts/check-versions.js
   ```
   Ловит: формат/дубли хешей, неизвестный parent, циклы, head не той ветки, коммит вне цепочки своей ветки (забыли обновить head), неизвестные облака/темы, повторные add. Ошибки исправь до показа пользователю.
6. **Покажи результат:** `index.html#v=b:<ветка>` (голова ветки) или `#v=c:<хеш>` (конкретный коммит).
7. **Не коммить в git и не пушь сам** — пользователь сначала проверяет локально. Коммит/пуш — только по его команде.

## Пример: продлить ветку «зелёная»

```js
// COMMITS — в конец:
{id:'3f9c2a1', date:'2026-11-14 10:30', parent:'0a67d21', branch:'зелёная', title:'субагенты: когда они экономят токены', src:'https://…', changes:[
  {op:'mod', cloud:'Оркестрация и экономия токенов', t:'Субагенты', x:'…новый текст по статье…'},
  {op:'add', cloud:'Оркестрация и экономия токенов', t:'Когда субагент не нужен', x:'…'}
]}
// BRANCHES:
'зелёная': {color:'#22a06b', head:'3f9c2a1'},
```
